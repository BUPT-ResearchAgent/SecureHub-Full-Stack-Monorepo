# WEBSEC-101 Web 安全防御基础讲义

> 受控预置教学讲义，供本地开发、比赛演示和明确授权的测试环境使用。它不是实时模型输出，也不是对外发布的教材副本；来源、处理时间、知识点关联和 Evidence 以课程资产详情中的持久化记录为准。

## 学习目标与前置

完成本讲义后，学生应能在一次 Web 功能评审中识别请求、身份、数据处理和外部访问之间的信任边界；能够解释输入校验、参数化查询、输出编码、最小权限和审计日志为何要组合使用；并能用检查清单验证修复是否覆盖了常见的回归风险。开始前应复习 HTTP 请求响应、认证与授权的区别，以及浏览器同源策略的基本约束。

## 1. 从请求边界开始建模

服务端不能把来自 URL、表单、Cookie、请求头或上游服务的字段自动视为可信。评审时先记录谁发起请求、服务端依据什么身份做授权、哪些字段会影响查询、文件、模板或网络访问，再为每一类数据定义允许的格式、长度、枚举值和失败处理方式。认证回答“你是谁”，授权回答“你能否访问当前对象”，两者都必须在服务端重新判断；只在前端隐藏按钮不能构成访问控制。

防御案例一：一个筛选页允许用户选择状态和排序方式。状态可以映射为参数化查询中的数据参数，排序字段却应先与服务端维护的允许列表比对，再映射到固定查询片段。日志只记录必要的请求标识、拒绝原因和审计上下文，不记录口令、会话令牌或完整敏感输入。修复后应以正常、边界和拒绝三类测试验证结果，而不是只观察页面能否加载。

## 2. 输入、查询与错误处理

输入验证应靠近业务语义：先区分数字、日期、标识符、受控枚举和自由文本，再采用长度限制、格式检查、白名单和规范化处理。参数化查询负责将数据与查询结构分离，但它不替代对象级授权、排序字段白名单、事务控制和错误处理。服务端返回给用户的错误信息应简洁且可操作，详细堆栈、查询结构和内部路径仅写入受控日志，并由教师案例复盘说明其风险边界。

检查点：每个接收外部输入的接口是否有明确的数据契约？不可参数化的位置是否有服务端白名单？失败时是否会泄露内部实现？修复后的自动化测试是否覆盖了允许与拒绝分支？这些问题用于识别和验证防御控制，不用于构造攻击载荷。

## 3. 浏览器输出与会话保护

浏览器会在 HTML 文本、属性、URL、脚本和 DOM API 等不同上下文解释数据。安全实现应优先使用框架的安全模板和文本节点 API，按照实际输出上下文做编码，并将内容安全策略作为补充控制。Cookie 应根据部署条件设置 Secure、HttpOnly 和合理的 SameSite 策略；敏感操作还应核验来源、一次性令牌或再认证要求。任何由用户提交的历史内容在模板升级后都需要回归检查。

防御案例二：评论内容进入课程讨论区时，服务端保存原始文本与审核状态，页面渲染只使用安全模板的文本输出能力；管理员的富文本能力采用受控组件、允许标签列表和版本审计。验收时分别检查普通文本、边界字符和被拒绝内容的处理记录，并确认 CSP 报告或安全日志能够关联到课程范围。

## 4. 文件与服务端请求的最小权限

上传功能需要同时验证文件名、扩展名、内容类型、大小、存储位置和后续访问权限，不能依赖客户端提供的 MIME 类型。文件应存放在不可直接执行的位置，通过受权下载或预览路径访问，并记录扫描和审核状态。服务端代为访问外部地址时，应限制协议、目标范围、重定向和超时，使用网络隔离与最小权限凭据；无法确认的目标应返回可审计的拒绝状态。

## 5. 练习、复盘与下一步

小组练习：为一个“课程资料检索与评论提交”功能画出数据流，列出输入、身份、数据库、文件和外部请求的边界；为每条边界选择一项预防控制、一项检测信号和一项验证方法。提交物应是一页防御检查表和一段解释，说明控制的适用范围及仍需人工复核的情况。完成后进入关联的输入验证、XSS、文件上传和 SSRF 练习，查看对应 Evidence 摘要，再参加质量通过的阶段作业。
